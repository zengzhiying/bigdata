# Hudi 核心概念：表类型 (Table Types)

## 概述

Apache Hudi 支持两种表类型，每种类型都针对不同的工作负载进行了优化：

- **Copy-on-Write (COW)** - 写时复制表
- **Merge-on-Read (MOR)** - 读时合并表

## 1. Copy-on-Write (COW) 表

### 1.1 工作原理

Copy-on-Write 表在每次写入（插入/更新/删除）时都会**重写整个数据文件**。数据以列式 Parquet 格式存储。

```
初始文件: file_v1.parquet [record1, record2, record3]
更新 record2 后: file_v2.parquet [record1, record2_updated, record3]
```

### 1.2 核心特点

| 特性 | 说明 |
|-----|------|
| **文件格式** | 仅 Parquet 文件 |
| **更新机制** | 重写包含更新记录的整个 Parquet 文件 |
| **写入延迟** | 较高（需要重写整个文件） |
| **读取延迟** | 较低（直接读取 Parquet 文件） |
| **存储开销** | 较低（无冗余数据） |
| **查询类型** | 仅支持 Snapshot Query（快照查询） |
| **压缩需求** | 不需要 |

### 1.3 适用场景

✅ **推荐使用场景：**
- 批处理工作负载，更新频率较低
- BI/分析查询，要求快速读取性能
- 数据仓库场景
- 不希望管理复杂压缩策略的简单用例

❌ **不推荐使用场景：**
- 高频更新的流式写入
- 对写入延迟要求极高的场景

### 1.4 配置示例

```scala
df.write.format("hudi")
  .option("hoodie.table.name", tableName)
  .option("hoodie.datasource.write.table.type", "COPY_ON_WRITE")  // 指定 COW 类型
  .option("hoodie.datasource.write.recordkey.field", "uuid")
  .option("hoodie.datasource.write.precombine.field", "ts")
  .option("hoodie.datasource.write.partitionpath.field", "city")
  .mode(SaveMode.Overwrite)
  .save(basePath)
```

## 2. Merge-on-Read (MOR) 表

### 2.1 工作原理

Merge-on-Read 表使用**基础文件（Parquet）+ 增量日志文件（Avro）**的组合存储方式：

- **Base Files**：列式 Parquet 文件，存储压缩后的数据
- **Delta Logs**：行式 Avro 文件，存储增量更新

```
Base File: file_v1.parquet [record1, record2, record3]
Delta Log: file_v1.log [update: record2_updated, insert: record4]
查询时合并: [record1, record2_updated, record3, record4]
```

### 2.2 核心特点

| 特性 | 说明 |
|-----|------|
| **文件格式** | Parquet（基础文件）+ Avro（增量日志） |
| **更新机制** | 追加增量日志，不重写基础文件 |
| **写入延迟** | 较低（仅追加日志） |
| **读取延迟** | 快照查询较高（需合并），读优化查询较低 |
| **存储开销** | 较高（压缩前有冗余数据） |
| **查询类型** | 支持 Snapshot Query 和 Read Optimized Query |
| **压缩需求** | 需要定期压缩（Compaction） |

### 2.3 查询类型

#### 2.3.1 Snapshot Query（快照查询）

**默认查询类型**，在读取时实时合并基础文件和增量日志，返回最新数据。

```scala
// 快照查询（默认）
val df = spark.read.format("hudi").load(basePath)
```

**特点：**
- ✅ 返回最新的完整数据
- ❌ 查询性能较慢（需要合并操作）

#### 2.3.2 Read Optimized Query（读优化查询）

**仅读取基础 Parquet 文件**，跳过增量日志，查询速度快但可能读取不到最新更新。

```scala
// 读优化查询
val df = spark.read.format("hudi")
  .option("hoodie.datasource.query.type", "read_optimized")
  .load(basePath)
```

**特点：**
- ✅ 查询性能最快（直接读 Parquet）
- ❌ 可能读不到最新更新（需等待压缩）

### 2.4 适用场景

✅ **推荐使用场景：**
- 流式数据摄入，高频更新
- 近实时数据可用性需求
- CDC（变更数据捕获）管道
- 写入延迟敏感的场景
- 需要在写入性能和读取性能间权衡的场景

❌ **不推荐使用场景：**
- 无法接受复杂运维（压缩调度）的场景
- 纯批处理、低频更新的场景

### 2.5 配置示例

```scala
df.write.format("hudi")
  .option("hoodie.table.name", tableName)
  .option("hoodie.datasource.write.table.type", "MERGE_ON_READ")  // 指定 MOR 类型
  .option("hoodie.datasource.write.recordkey.field", "uuid")
  .option("hoodie.datasource.write.precombine.field", "ts")
  .option("hoodie.datasource.write.partitionpath.field", "city")
  .option("hoodie.compact.inline", "false")  // 禁用内联压缩
  .mode(SaveMode.Overwrite)
  .save(basePath)
```

## 3. COW vs MOR 对比

### 3.1 详细对比表

| 维度 | Copy-on-Write (COW) | Merge-on-Read (MOR) |
|------|---------------------|---------------------|
| **数据文件格式** | Parquet | Parquet + Avro |
| **更新机制** | 重写整个文件 | 追加增量日志 |
| **写入延迟** | 高 | 低 |
| **读取延迟（快照）** | 低 | 高 |
| **读取延迟（读优化）** | 不适用 | 最低 |
| **存储效率** | 高 | 低（压缩前） |
| **查询复杂度** | 简单 | 复杂（需合并） |
| **压缩需求** | 无 | 必需 |
| **运维复杂度** | 低 | 高 |
| **适合工作负载** | 读密集型 | 写密集型 |
| **数据新鲜度** | 写入即可见 | 快照查询可见，读优化查询需压缩 |

### 3.2 性能对比

#### 写入性能
```
MOR 写入速度 > COW 写入速度
MOR: 仅追加日志（~100ms）
COW: 重写整个文件（~1s+，取决于文件大小）
```

#### 读取性能
```
COW 快照查询 ≈ MOR 读优化查询 > MOR 快照查询
COW/MOR-RO: 直接读 Parquet（~500ms）
MOR Snapshot: 读 Parquet + 合并 Avro（~2s+）
```

### 3.3 选择决策树

```
需要高频更新？
├─ 是 → 写入延迟敏感？
│        ├─ 是 → MOR（配合异步压缩）
│        └─ 否 → COW 或 MOR
└─ 否 → 查询性能最重要？
         ├─ 是 → COW
         └─ 否 → COW（更简单的运维）
```

## 4. 关键配置参数

### 4.1 表类型配置

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| `hoodie.datasource.write.table.type` | 表类型 | COPY_ON_WRITE, MERGE_ON_READ | COPY_ON_WRITE |
| `hoodie.datasource.write.recordkey.field` | 主键字段 | 字段名（逗号分隔） | - |
| `hoodie.datasource.write.precombine.field` | 预合并字段（用于去重） | 字段名 | - |
| `hoodie.datasource.write.partitionpath.field` | 分区字段 | 字段名（逗号分隔） | - |

### 4.2 MOR 特有配置

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `hoodie.compact.inline` | 是否启用内联压缩 | false |
| `hoodie.compact.inline.max.delta.commits` | 触发压缩的最大增量提交数 | 5 |
| `hoodie.datasource.query.type` | 查询类型 | snapshot |

## 5. 最佳实践

### 5.1 COW 表最佳实践

1. **合理设计分区**：避免单个分区文件过大导致更新缓慢
2. **批量更新**：尽量批量提交更新，减少重写次数
3. **监控文件大小**：使用 Clustering 优化小文件问题
4. **选择合适的文件大小**：推荐 128MB-512MB

### 5.2 MOR 表最佳实践

1. **配置压缩策略**：
   - 异步压缩：使用独立的压缩作业
   - 压缩频率：根据增量日志大小调整
   
2. **查询类型选择**：
   - 实时仪表盘：使用 Snapshot Query
   - 批量分析：使用 Read Optimized Query
   
3. **监控增量日志大小**：避免日志文件过多影响查询性能

4. **合理设置压缩参数**：
   ```scala
   .option("hoodie.compact.inline.max.delta.commits", "10")
   .option("hoodie.parquet.small.file.limit", "104857600") // 100MB
   ```

### 5.3 通用最佳实践

1. **正确设置主键和预合并字段**：
   - recordkey：业务唯一标识
   - precombine：时间戳或版本号（用于去重时选择最新记录）

2. **启用元数据表**（Hudi 0.11+）：
   ```scala
   .option("hoodie.metadata.enable", "true")
   ```

3. **合理设置并行度**：
   ```scala
   .option("hoodie.insert.shuffle.parallelism", "2")
   .option("hoodie.upsert.shuffle.parallelism", "2")
   ```

## 6. 常见问题

### Q1: 如何从 COW 表迁移到 MOR 表？

**A:** Hudi 不支持直接转换表类型，需要创建新表并迁移数据：

```scala
// 1. 读取 COW 表数据
val cowData = spark.read.format("hudi").load("cow_table_path")

// 2. 写入新的 MOR 表
cowData.write.format("hudi")
  .option("hoodie.datasource.write.table.type", "MERGE_ON_READ")
  .option("hoodie.table.name", "new_mor_table")
  // ... 其他配置
  .save("mor_table_path")
```

### Q2: MOR 表的压缩会影响写入性能吗？

**A:** 
- **内联压缩**（inline compaction）：会阻塞写入，影响写入延迟
- **异步压缩**（async compaction）：不阻塞写入，推荐使用

### Q3: Read Optimized Query 读不到最新数据怎么办？

**A:** Read Optimized Query 仅读取基础文件，需要等待压缩完成。解决方案：
1. 使用 Snapshot Query 获取最新数据
2. 调整压缩频率，更频繁地执行压缩
3. 使用内联压缩（会影响写入性能）

### Q4: 如何查看表的类型？

**A:** 查看 `.hoodie/hoodie.properties` 文件：

```bash
cat /path/to/table/.hoodie/hoodie.properties | grep hoodie.table.type
# 输出示例：
# hoodie.table.type=MERGE_ON_READ
```
