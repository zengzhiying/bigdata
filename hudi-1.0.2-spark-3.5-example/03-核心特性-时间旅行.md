# Hudi 核心特性：时间旅行 (Time Travel)

## 概述

时间旅行（Time Travel）是 Apache Hudi 的一项强大特性，允许用户**查询表在历史任何时间点的数据快照**。通过指定提交时间戳，可以访问表的历史版本，这对于审计、调试、数据恢复和合规性至关重要。

### 核心价值

- **数据审计**：追溯数据在任意时间点的状态
- **错误恢复**：从错误的更新或删除中恢复数据
- **调试分析**：定位数据问题发生的时间点
- **合规要求**：满足监管机构对历史数据的查询需求
- **A/B 测试**：比较不同时间点的数据版本

---

## 1. 时间旅行基础

### 1.1 工作原理

Hudi 的时间旅行基于其**多版本并发控制（MVCC）**架构：

```
Timeline: [Commit1] → [Commit2] → [Commit3] → [Commit4]
            ↓            ↓            ↓            ↓
          V1           V2           V3         V4 (current)

Time Travel Query:
  as.of.instant = Commit2 → Returns data snapshot at V2
```

每个提交（commit）都包含完整的元数据，允许 Hudi 重构该时间点的数据快照。

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **Commit Time** | 每次写入操作的时间戳，格式：yyyyMMddHHmmssSSS |
| **Instant** | 时间线上的一个时间点，对应一次提交 |
| **Snapshot** | 某个提交时刻的完整数据视图 |
| **Timeline** | 所有提交的有序序列 |
| **Retention** | 保留的历史提交数量 |

### 1.3 支持的表类型

| 表类型 | 时间旅行支持 | 说明 |
|--------|-------------|------|
| **Copy-on-Write (COW)** | ✅ 完全支持 | 直接读取历史 Parquet 文件 |
| **Merge-on-Read (MOR)** | ✅ 完全支持 | 读取历史基础文件 + 增量日志 |

## 2. 基本用法

### 2.1 配置参数

使用时间旅行的核心参数：

```scala
spark.read.format("hudi")
  .option("as.of.instant", "<commit_timestamp>")
  .load(basePath)
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `as.of.instant` | 指定要查询的提交时间戳 | "20231201120000000" |

### 2.2 获取提交时间

**方法 1：从元数据列获取**

```scala
val df = spark.read.format("hudi").load(basePath)

// 查看所有提交时间
df.select("_hoodie_commit_time")
  .distinct()
  .orderBy("_hoodie_commit_time")
  .show()

// 获取最新提交时间
val latestCommit = df.select("_hoodie_commit_time")
  .orderBy(desc("_hoodie_commit_time"))
  .first()
  .getString(0)
```

**方法 2：从 Timeline 获取**

```scala
import org.apache.hudi.common.table.HoodieTableMetaClient
import org.apache.hadoop.fs.Path

val metaClient = HoodieTableMetaClient.builder()
  .setConf(spark.sparkContext.hadoopConfiguration)
  .setBasePath(basePath)
  .build()

val timeline = metaClient.getActiveTimeline.getCommitsTimeline
val commits = timeline.getInstants.iterator()

while (commits.hasNext) {
  val instant = commits.next()
  println(s"Commit: ${instant.getTimestamp}")
}
```

### 2.3 基本示例

```scala
// 写入初始数据
df1.write.format("hudi")
  .option("hoodie.table.name", "trips")
  .save(basePath)

val commit1 = spark.read.format("hudi").load(basePath)
  .select("_hoodie_commit_time").first().getString(0)

Thread.sleep(2000)

// 更新数据
df2.write.format("hudi")
  .option("hoodie.datasource.write.operation", "upsert")
  .mode(SaveMode.Append)
  .save(basePath)

val commit2 = spark.read.format("hudi").load(basePath)
  .select("_hoodie_commit_time").first().getString(0)

// 时间旅行到第一个版本
val version1 = spark.read.format("hudi")
  .option("as.of.instant", commit1)
  .load(basePath)

version1.show()  // 显示初始数据

// 查询当前版本
val current = spark.read.format("hudi").load(basePath)
current.show()  // 显示更新后的数据
```

## 3. 高级特性

### 3.1 跨版本比较

比较不同时间点的数据差异：

```scala
// 读取两个不同版本
val v1 = spark.read.format("hudi")
  .option("as.of.instant", commit1)
  .load(basePath)
  .select(col("id").as("id_v1"), col("price").as("price_v1"))

val v2 = spark.read.format("hudi")
  .option("as.of.instant", commit2)
  .load(basePath)
  .select(col("id").as("id_v2"), col("price").as("price_v2"))

// Join 并比较
val changes = v1.join(v2, v1("id_v1") === v2("id_v2"), "inner")
  .filter(col("price_v1") =!= col("price_v2"))
  .select(
    col("id_v1").as("id"),
    col("price_v1").as("old_price"),
    col("price_v2").as("new_price"),
    (col("price_v2") - col("price_v1")).as("price_change")
  )

changes.show()
```

### 3.2 审计追踪

追踪特定记录的历史变更：

```scala
val commits = Seq(commit1, commit2, commit3, commit4)

println("Order-001 历史变更:")
commits.foreach { commit =>
  val snapshot = spark.read.format("hudi")
    .option("as.of.instant", commit)
    .load(basePath)
  
  val record = snapshot.filter("order_id = 'order-001'")
    .select("status", "price")
    .first()
  
  println(s"Commit $commit: status=${record.getString(0)}, price=${record.getDouble(1)}")
}
```

### 3.3 时间点分析

生成历史时间点的报表：

```scala
val reportDates = Seq(
  ("2023-12-01", commit1),
  ("2023-12-02", commit2),
  ("2023-12-03", commit3)
)

println("每日收入分析:")
reportDates.foreach { case (date, commit) =>
  val snapshot = spark.read.format("hudi")
    .option("as.of.instant", commit)
    .load(basePath)
  
  val totalRevenue = snapshot
    .withColumn("revenue", col("price") * col("quantity"))
    .agg(sum("revenue"))
    .first()
    .getDouble(0)
  
  println(f"$date: $$${totalRevenue}%.2f")
}
```

### 3.4 数据恢复

从错误的更新中恢复：

```scala
// 1. 识别错误发生前的提交
val lastGoodCommit = commit2  // 假设 commit3 引入了错误

// 2. 读取正确的数据
val correctData = spark.read.format("hudi")
  .option("as.of.instant", lastGoodCommit)
  .load(basePath)

// 3. 重新写入以覆盖错误数据
correctData
  .withColumn("ts", lit(System.currentTimeMillis()))
  .write.format("hudi")
  .option("hoodie.datasource.write.operation", "upsert")
  .mode(SaveMode.Append)
  .save(basePath)

println("数据已恢复到上次正确状态")
```

## 4. 配置与管理

### 4.1 保留策略配置

控制历史提交的保留时间：

| 参数 | 说明 | 默认值 | 推荐值 |
|------|------|--------|--------|
| `hoodie.cleaner.commits.retained` | 清理时保留的提交数 | 10 | 20-30（根据需求） |
| `hoodie.keep.min.commits` | 最小保留提交数 | 20 | 30-50 |
| `hoodie.keep.max.commits` | 最大保留提交数 | 30 | 50-100 |
| `hoodie.cleaner.policy` | 清理策略 | KEEP_LATEST_COMMITS | - |

**配置示例：**

```scala
df.write.format("hudi")
  .option("hoodie.table.name", tableName)
  .option("hoodie.cleaner.commits.retained", "30")     // 保留最近 30 个提交
  .option("hoodie.keep.min.commits", "40")             // 最小保留 40 个
  .option("hoodie.keep.max.commits", "50")             // 最大保留 50 个
  .option("hoodie.cleaner.policy", "KEEP_LATEST_COMMITS")
  .save(basePath)
```

### 4.2 清理策略

**KEEP_LATEST_COMMITS（推荐）：**
- 基于提交数量保留
- 适合大多数场景

**KEEP_LATEST_FILE_VERSIONS：**
- 基于文件版本保留
- 适合频繁更新的场景

**KEEP_LATEST_BY_HOURS：**
- 基于时间保留
- 适合有明确时间要求的场景

### 4.3 存储成本优化

**策略 1：分层存储**

```scala
// 热数据：保留 7 天（频繁访问）
.option("hoodie.cleaner.commits.retained", "168")  // 7天 * 24小时

// 温数据：保留 30 天（偶尔访问）
.option("hoodie.cleaner.commits.retained", "720")  // 30天 * 24小时

// 冷数据：归档到 S3 Glacier（长期存储）
```

**策略 2：压缩旧提交**

定期运行 Compaction 以减少小文件数量，降低存储开销。

## 5. 实战场景

### 5.1 场景 1：合规审计

**需求**：监管机构要求提供 2023-12-01 的完整账户余额报告。

```scala
val auditDate = "20231201120000000"

val auditReport = spark.read.format("hudi")
  .option("as.of.instant", auditDate)
  .load(basePath)

auditReport.groupBy("account_type")
  .agg(
    count("*").as("accounts"),
    sum("balance").as("total_balance")
  )
  .write
  .format("parquet")
  .save(s"s3://audit-reports/balance-report-$auditDate")

println(s"审计报告已生成：$auditDate")
```

### 5.2 场景 2：错误恢复

**需求**：周二早晨发现周一晚上的批处理作业错误地将所有价格翻倍。

```scala
// 1. 识别错误提交
val errorCommit = "20231205020000000"
val lastGoodCommit = "20231204230000000"

// 2. 对比数据
val goodData = spark.read.format("hudi")
  .option("as.of.instant", lastGoodCommit)
  .load(basePath)

val badData = spark.read.format("hudi")
  .option("as.of.instant", errorCommit)
  .load(basePath)

// 验证问题
val avgPriceGood = goodData.agg(avg("price")).first().getDouble(0)
val avgPriceBad = badData.agg(avg("price")).first().getDouble(0)

println(s"正常平均价格: $avgPriceGood")
println(s"错误平均价格: $avgPriceBad")
println(s"倍数: ${avgPriceBad / avgPriceGood}")

// 3. 恢复数据
goodData
  .withColumn("ts", lit(System.currentTimeMillis()))
  .write.format("hudi")
  .option("hoodie.datasource.write.operation", "upsert")
  .mode(SaveMode.Append)
  .save(basePath)

println("数据已恢复")
```

### 5.3 场景 3：调试数据问题

**需求**：客户投诉订单状态不正确，需要追踪订单状态的历史变更。

```scala
val orderId = "order-12345"

// 获取所有提交时间
val commits = spark.read.format("hudi").load(basePath)
  .select("_hoodie_commit_time")
  .distinct()
  .orderBy("_hoodie_commit_time")
  .collect()
  .map(_.getString(0))

println(s"订单 $orderId 状态变更历史:")

commits.foreach { commit =>
  val snapshot = spark.read.format("hudi")
    .option("as.of.instant", commit)
    .load(basePath)
  
  val orderOpt = snapshot.filter(s"order_id = '$orderId'").collect()
  
  if (orderOpt.nonEmpty) {
    val order = orderOpt.head
    val status = order.getAs[String]("status")
    val timestamp = order.getAs[Long]("ts")
    
    println(f"[$commit] status=$status%-12s ts=$timestamp")
  }
}
```

## 7. 常见问题 (FAQ)

### Q1: 时间旅行查询失败，提示"Instant not found"？

**A:** 该提交已被清理。解决方案：
1. 增加 `hoodie.cleaner.commits.retained` 配置
2. 检查提交时间是否正确（格式：yyyyMMddHHmmssSSS）
3. 确认该提交未被归档

### Q2: 时间旅行查询很慢，如何优化？

**A:** 
1. **COW 表**：查询速度通常较快，检查分区裁剪
2. **MOR 表**：定期压缩以减少增量日志
3. 缓存常用的历史快照
4. 使用分区过滤减少扫描范围

### Q3: 如何查看表的所有历史提交？

**A:** 

```scala
// 方法 1: 从数据中读取
val commits = spark.read.format("hudi").load(basePath)
  .select("_hoodie_commit_time")
  .distinct()
  .orderBy("_hoodie_commit_time")
  .collect()

commits.foreach(row => println(row.getString(0)))

// 方法 2: 使用 Hudi CLI
// bin/hudi-cli.sh
// > connect --path /path/to/table
// > commits show
```

### Q4: 时间旅行是否支持删除的记录？

**A:** 是的，如果记录在指定的提交时间存在，时间旅行可以查询到已删除的记录。

```scala
// 假设 record-123 在 commit2 被删除
val beforeDelete = spark.read.format("hudi")
  .option("as.of.instant", commit1)
  .load(basePath)
  .filter("id = 'record-123'")

beforeDelete.show()  // 可以查看到删除前的数据
```

### Q5: 能否基于业务日期而非提交时间进行时间旅行？

**A:** Hudi 仅支持基于提交时间的时间旅行。如需基于业务日期查询，可以：

```scala
// 方案 1: 维护业务日期到提交时间的映射
val dateToCommitMap = Map(
  "2023-12-01" -> "20231201235959999",
  "2023-12-02" -> "20231202235959999"
)

val businessDate = "2023-12-01"
val commit = dateToCommitMap(businessDate)

val data = spark.read.format("hudi")
  .option("as.of.instant", commit)
  .load(basePath)

// 方案 2: 结合业务日期字段过滤
val data = spark.read.format("hudi")
  .option("as.of.instant", commit)
  .load(basePath)
  .filter("business_date = '2023-12-01'")
```

### Q6: 如何防止重要历史数据被清理？

**A:** 

```scala
// 配置足够长的保留期
.option("hoodie.cleaner.commits.retained", "365")  // 保留 1 年

// 或者禁用自动清理
.option("hoodie.clean.automatic", "false")

// 手动控制清理时机
```

## 11. 性能基准

**COW 表时间旅行性能：**
- 查询历史版本：与查询当前版本相当（直接读 Parquet）
- 适合频繁的历史查询

**MOR 表时间旅行性能：**
- 查询历史版本：需合并基础文件和增量日志，较慢
- 建议定期压缩以提升性能

**存储开销：**
- 每保留 1 个提交 ≈ 增加 5-10% 存储空间（取决于更新比例）
- 平衡保留期与存储成本
