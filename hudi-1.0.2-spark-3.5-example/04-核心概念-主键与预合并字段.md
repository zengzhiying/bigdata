# Hudi 核心概念：主键与预合并字段 (Record Key & Precombine Field)

## 概述

主键（Record Key）和预合并字段（Precombine Field）是 Apache Hudi 中两个最关键的配置项，它们共同决定了 Hudi 如何识别记录、处理更新和去重数据。

### 核心概念

- **Record Key（主键）**：唯一标识表中每条记录的字段，类似于传统数据库的主键
- **Precombine Field（预合并字段）**：当存在重复主键时，用于决定保留哪条记录的字段

---

## 1. Record Key（主键）

### 1.1 定义与作用

Record Key 是 Hudi 表中每条记录的**唯一标识符**，用于：

- **唯一性标识**：区分表中的不同记录
- **Upsert 操作**：判断是插入新记录还是更新现有记录
- **去重**：识别并合并重复记录
- **索引构建**：加速查询和更新操作

### 1.2 配置方式

```scala
.option("hoodie.datasource.write.recordkey.field", "user_id")
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `hoodie.datasource.write.recordkey.field` | 指定主键字段 | "user_id" |

### 1.3 单字段主键

**最常见的场景**，使用单个字段作为主键：

```scala
val df = Seq(
  ("U001", "Alice", "alice@example.com"),
  ("U002", "Bob", "bob@example.com"),
  ("U003", "Carol", "carol@example.com")
).toDF("user_id", "name", "email")

df.write.format("hudi")
  .option("hoodie.table.name", "users")
  .option("hoodie.datasource.write.recordkey.field", "user_id")  // 单字段主键
  .option("hoodie.datasource.write.precombine.field", "ts")
  .save(basePath)
```

**适用场景：**
- 用户表：user_id
- 订单表：order_id
- 产品表：product_id
- 事件表：event_id (UUID)

### 1.4 复合主键（Composite Key）

当单个字段无法唯一标识记录时，使用**多个字段组合**作为主键：

```scala
// 多租户场景：tenant_id + sensor_id
.option("hoodie.datasource.write.recordkey.field", "tenant_id,sensor_id")

// 时序数据：device_id + timestamp
.option("hoodie.datasource.write.recordkey.field", "device_id,timestamp")

// 地理数据：country + city + store_id
.option("hoodie.datasource.write.recordkey.field", "country,city,store_id")
```

**复合主键示例：**

```scala
val sensorData = Seq(
  ("tenant-A", "sensor-001", 22.5, 1701388800000L),
  ("tenant-A", "sensor-002", 23.1, 1701388800000L),
  ("tenant-B", "sensor-001", 21.8, 1701388800000L)  // 不同租户，相同 sensor_id
).toDF("tenant_id", "sensor_id", "temperature", "timestamp")

sensorData.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "tenant_id,sensor_id")
  .option("hoodie.datasource.write.precombine.field", "timestamp")
  .save(basePath)
```

**注意事项：**
- 字段顺序重要：`"field1,field2"` ≠ `"field2,field1"`
- 所有字段必须非空
- 字段之间用逗号分隔，无空格

### 1.5 Record Key 的内部表示

Hudi 将主键存储在元数据列 `_hoodie_record_key` 中：

```scala
val df = spark.read.format("hudi").load(basePath)

df.select("user_id", "_hoodie_record_key", "name").show()

// 输出：
// +--------+-------------------+-------+
// | user_id| _hoodie_record_key|   name|
// +--------+-------------------+-------+
// |    U001|               U001|  Alice|
// |    U002|               U002|    Bob|
// +--------+-------------------+-------+

// 复合主键示例：
// +----------+-----------+-----------------------------+
// | tenant_id| sensor_id | _hoodie_record_key          |
// +----------+-----------+-----------------------------+
// | tenant-A | sensor-001| tenant-A:sensor-001         |
// | tenant-B | sensor-001| tenant-B:sensor-001         |
// +----------+-----------+-----------------------------+
```

### 1.6 Record Key 最佳实践

#### ✅ 推荐做法

1. **使用业务主键**
   ```scala
   // 自然主键
   .option("hoodie.datasource.write.recordkey.field", "order_id")
   ```

2. **使用 UUID**
   ```scala
   val df = rawDf.withColumn("id", expr("uuid()"))
   .option("hoodie.datasource.write.recordkey.field", "id")
   ```

3. **确保非空**
   ```scala
   // 写入前过滤空值
   val cleanDf = df.filter(col("user_id").isNotNull)
   ```

4. **不可变性**
   - 选择永远不会改变的字段
   - 避免使用可能更新的字段（如 email、phone）

#### ❌ 应避免的做法

1. **使用非唯一字段**
   ```scala
   // 错误：city 不唯一
   .option("hoodie.datasource.write.recordkey.field", "city")
   ```

2. **允许空值**
   ```scala
   // 错误：可能产生 null 主键
   df.write.format("hudi")
     .option("hoodie.datasource.write.recordkey.field", "nullable_field")
   ```

3. **使用可变字段**
   ```scala
   // 不推荐：email 可能更改
   .option("hoodie.datasource.write.recordkey.field", "email")
   ```

4. **不指定主键**
   ```scala
   // 错误：Hudi 会自动生成 UUID，导致无法正确 upsert
   df.write.format("hudi").save(basePath)  // 缺少 recordkey.field
   ```

## 2. Precombine Field（预合并字段）

### 2.1 定义与作用

Precombine Field 用于**去重和选择记录**。当存在多个具有相同 Record Key 的记录时，Hudi 根据 Precombine Field 的值选择保留哪条记录。

**核心规则：**
- 比较 Precombine Field 的值
- **保留值较大的记录**
- 丢弃值较小的记录

### 2.2 配置方式

```scala
.option("hoodie.datasource.write.precombine.field", "updated_at")
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `hoodie.datasource.write.precombine.field` | 指定预合并字段 | "updated_at" |

### 2.3 工作原理

**场景：同一批次中有重复的 Record Key**

```scala
val data = Seq(
  ("ORD-001", 1200.00, 1701388800000L),  // 旧时间戳
  ("ORD-001", 1500.00, 1701475200000L)   // 新时间戳 - 将被保留
).toDF("order_id", "amount", "updated_ts")

data.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "order_id")
  .option("hoodie.datasource.write.precombine.field", "updated_ts")
  .save(basePath)

// 结果：只保留 updated_ts = 1701475200000L 的记录
```

**Hudi 处理流程：**

```
1. 检测到 order_id = "ORD-001" 有两条记录
2. 比较 precombine 字段：1701388800000L vs 1701475200000L
3. 保留较大值：1701475200000L
4. 写入金额为 1500.00 的记录
```

### 2.4 支持的数据类型

Precombine Field 必须是**可比较类型**：

| 数据类型 | 是否支持 | 示例 | 备注 |
|----------|---------|------|------|
| Long | ✅ | `1701388800000L` | 时间戳（推荐） |
| Integer | ✅ | `1, 2, 3` | 版本号 |
| Timestamp | ✅ | `Timestamp("2023-12-01 12:00:00")` | SQL 时间戳 |
| String | ✅ | `"2023-12-01T12:00:00Z"` | ISO 格式字符串 |
| Double | ✅ | `1.0, 2.0` | 序列号 |
| Date | ✅ | `Date("2023-12-01")` | 日期 |
| Array | ❌ | - | 不支持 |
| Struct | ❌ | - | 不支持 |
| Map | ❌ | - | 不支持 |

### 2.5 常见使用场景

#### 场景 1：事件流处理（Event Streaming）

```scala
// Kafka 消息流
val eventStream = Seq(
  ("event-001", "click", 1701388800000L),
  ("event-001", "purchase", 1701388900000L)  // 同一事件的后续更新
).toDF("event_id", "event_type", "event_time")

eventStream.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "event_id")
  .option("hoodie.datasource.write.precombine.field", "event_time")
  .save(basePath)

// 结果：保留 event_time 最大的记录（purchase）
```

#### 场景 2：数据库 CDC（Change Data Capture）

```scala
// 数据库变更捕获
val cdc = Seq(
  ("user-001", "Alice", "alice@old.com", 1701388800000L),  // 旧更新
  ("user-001", "Alice", "alice@new.com", 1701475200000L)   // 新更新
).toDF("user_id", "name", "email", "db_updated_at")

cdc.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "user_id")
  .option("hoodie.datasource.write.precombine.field", "db_updated_at")
  .save(basePath)

// 结果：保留最新的数据库更新
```

#### 场景 3：版本化数据

```scala
// 使用版本号而非时间戳
val versioned = Seq(
  ("doc-001", "Content V1", 1),
  ("doc-001", "Content V2", 2),
  ("doc-001", "Content V3", 3)
).toDF("doc_id", "content", "version")

versioned.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "doc_id")
  .option("hoodie.datasource.write.precombine.field", "version")
  .save(basePath)

// 结果：保留 version = 3 的记录
```

### 2.6 处理迟到数据（Late-Arriving Data）

Precombine Field 的一个重要应用是**处理乱序数据**：

```scala
// 写入较新的数据
val newData = Seq(
  ("sensor-001", 25.0, 1701475200000L)
).toDF("sensor_id", "temperature", "timestamp")

newData.write.format("hudi")
  .option("hoodie.datasource.write.recordkey.field", "sensor_id")
  .option("hoodie.datasource.write.precombine.field", "timestamp")
  .save(basePath)

// 稍后，迟到的旧数据到达
val lateData = Seq(
  ("sensor-001", 20.0, 1701388800000L)  // 更早的时间戳
).toDF("sensor_id", "temperature", "timestamp")

lateData.write.format("hudi")
  .option("hoodie.datasource.write.operation", "upsert")
  .option("hoodie.datasource.write.recordkey.field", "sensor_id")
  .option("hoodie.datasource.write.precombine.field", "timestamp")
  .mode(SaveMode.Append)
  .save(basePath)

// 结果：旧数据被丢弃，保留 timestamp 较大的记录（25.0）
```

### 2.7 Precombine Field 最佳实践

#### ✅ 推荐做法

1. **使用事件时间（Event Time）**
   ```scala
   .option("hoodie.datasource.write.precombine.field", "event_time")
   ```

2. **使用数据库更新时间**
   ```scala
   .option("hoodie.datasource.write.precombine.field", "db_updated_at")
   ```

3. **使用单调递增的版本号**
   ```scala
   .option("hoodie.datasource.write.precombine.field", "version")
   ```

4. **确保非空**
   ```scala
   val cleanDf = df.filter(col("updated_at").isNotNull)
   ```

5. **文档化选择逻辑**
   ```scala
   // 明确记录为什么选择此字段
   // Precombine field: event_time - represents when event actually occurred
   .option("hoodie.datasource.write.precombine.field", "event_time")
   ```

#### ❌ 应避免的做法

1. **使用随机值**
   ```scala
   // 错误：defeats deduplication purpose
   .option("hoodie.datasource.write.precombine.field", "random_value")
   ```

2. **使用 current_timestamp()**
   ```scala
   // 错误：所有记录相同值，去重失效
   val df = rawDf.withColumn("ts", current_timestamp())
   ```

3. **允许空值**
   ```scala
   // 错误：空值导致不可预测的行为
   .option("hoodie.datasource.write.precombine.field", "nullable_timestamp")
   ```

4. **使用非单调字段**
   ```scala
   // 不推荐：price 不单调递增
   .option("hoodie.datasource.write.precombine.field", "price")
   ```

## 3. Record Key 与 Precombine Field 的协同

### 3.1 两者的关系

| 维度 | Record Key | Precombine Field |
|------|-----------|------------------|
| **用途** | 唯一标识记录 | 选择重复记录中的获胜者 |
| **唯一性要求** | 必须唯一（或组合唯一） | 无需唯一 |
| **Null 值** | 不允许 | 不允许 |
| **数据类型** | 任意（通常字符串） | 可比较类型 |
| **可变性** | 不可变 | 可变（应单调递增） |

### 3.2 完整配置示例

```scala
val df = Seq(
  ("U001", "Alice", "alice@example.com", 28, 1701388800000L),
  ("U002", "Bob", "bob@example.com", 35, 1701388800000L)
).toDF("user_id", "name", "email", "age", "updated_at")

df.write.format("hudi")
  .option("hoodie.table.name", "users")
  .option("hoodie.datasource.write.table.type", "COPY_ON_WRITE")
  
  // Record Key: 唯一标识用户
  .option("hoodie.datasource.write.recordkey.field", "user_id")
  
  // Precombine Field: 保留最新更新
  .option("hoodie.datasource.write.precombine.field", "updated_at")
  
  .option("hoodie.datasource.write.partitionpath.field", "")
  .mode(SaveMode.Overwrite)
  .save(basePath)
```

### 3.3 Upsert 操作流程

当执行 upsert 时，Hudi 的处理逻辑：

```
1. 使用 Record Key 查找是否存在匹配记录
   ├─ 如果不存在 → INSERT 新记录
   └─ 如果存在 → 进入步骤 2

2. 比较 Precombine Field 值
   ├─ 新记录值 > 现有记录值 → UPDATE（保留新记录）
   └─ 新记录值 ≤ 现有记录值 → 忽略新记录（保留旧记录）
```

**示例：**

```scala
// 现有记录
// user_id = "U001", name = "Alice", updated_at = 1000

// 尝试 upsert 新记录
val update1 = Seq(
  ("U001", "Alice Updated", 2000L)  // 更新时间戳更新
).toDF("user_id", "name", "updated_at")

// 结果：UPDATE（2000 > 1000）

val update2 = Seq(
  ("U001", "Alice Old", 500L)  // 更旧的时间戳
).toDF("user_id", "name", "updated_at")

// 结果：忽略（500 < 1000）
```

## 5. 数据质量验证

### 5.1 完整验证函数

```scala
import org.apache.spark.sql.DataFrame
import org.apache.spark.sql.functions._

def validateHudiWriteData(
  df: DataFrame,
  recordKeyFields: Seq[String],
  precombineField: String
): (Boolean, Seq[String]) = {
  
  val errors = scala.collection.mutable.ArrayBuffer[String]()
  
  // 1. 检查 Record Key 字段是否存在
  recordKeyFields.foreach { field =>
    if (!df.columns.contains(field)) {
      errors += s"Record key field '$field' not found in DataFrame"
    }
  }
  
  // 2. 检查 Precombine 字段是否存在
  if (!df.columns.contains(precombineField)) {
    errors += s"Precombine field '$precombineField' not found in DataFrame"
  }
  
  if (errors.nonEmpty) {
    return (false, errors.toSeq)
  }
  
  // 3. 检查 Record Key 空值
  recordKeyFields.foreach { field =>
    val nullCount = df.filter(col(field).isNull).count()
    if (nullCount > 0) {
      errors += s"Found $nullCount null values in record key field '$field'"
    }
  }
  
  // 4. 检查 Precombine 字段空值
  val nullPrecombine = df.filter(col(precombineField).isNull).count()
  if (nullPrecombine > 0) {
    errors += s"Found $nullPrecombine null values in precombine field '$precombineField'"
  }
  
  // 5. 检查重复的 Record Key
  val keyColumns = recordKeyFields.map(col)
  val duplicates = df.groupBy(keyColumns: _*).count().filter("count > 1")
  val duplicateCount = duplicates.count()
  
  if (duplicateCount > 0) {
    errors += s"Found $duplicateCount duplicate record keys (will be deduplicated using precombine field)"
    // 这不是错误，只是警告
  }
  
  (errors.isEmpty, errors.toSeq)
}

// 使用示例
val (isValid, validationErrors) = validateHudiWriteData(
  df = myDataFrame,
  recordKeyFields = Seq("user_id"),
  precombineField = "updated_at"
)

if (isValid) {
  println("✓ Data validation passed")
  myDataFrame.write.format("hudi").save(basePath)
} else {
  println("✗ Data validation failed:")
  validationErrors.foreach(err => println(s"  - $err"))
}
```

## 6. 常见问题 (FAQ)

### Q1: Record Key 和 Precombine Field 可以是同一个字段吗？

**A:** 理论上可以，但**不推荐**。这会导致逻辑混乱：

```scala
// 不推荐
.option("hoodie.datasource.write.recordkey.field", "event_id")
.option("hoodie.datasource.write.precombine.field", "event_id")

// 问题：当 event_id 相同时，如何选择记录？
```

推荐使用独立的时间戳或版本字段作为 Precombine Field。

### Q2: 如果不指定 Precombine Field 会怎样？

**A:** Hudi **要求必须指定** Precombine Field，否则写入会失败。

### Q3: Precombine Field 相同时，Hudi 如何选择记录？

**A:** 当 Precombine Field 值相同时，Hudi 的行为是**不确定的**（non-deterministic）。应避免这种情况：

```scala
// 避免：两条记录有相同的 precombine 值
("U001", 100.0, 1000L)
("U001", 200.0, 1000L)  // 相同 timestamp，不确定保留哪条
```

**解决方案：**
- 使用更高精度的时间戳（毫秒级）
- 添加额外的序列号字段
- 使用复合 Precombine Field（如果支持）

### Q4: 可以在写入后更改 Record Key 或 Precombine Field 吗？

**A:** **不可以**。一旦表创建，这两个字段配置应保持不变。更改会导致：
- Upsert 逻辑失效
- 数据重复
- 索引损坏

### Q5: 如何处理 Record Key 字段值变更的情况？

**A:** Record Key 应该是**不可变的**。如果业务需求确实需要更改主键：

```scala
// 方案 1: 删除旧记录，插入新记录
val deleteOld = Seq(("old_key", ...)).toDF(...)
  .write.format("hudi")
  .option("hoodie.datasource.write.operation", "delete")
  .save(basePath)

val insertNew = Seq(("new_key", ...)).toDF(...)
  .write.format("hudi")
  .option("hoodie.datasource.write.operation", "insert")
  .save(basePath)

// 方案 2: 使用不可变的代理键（UUID）
val df = rawDf.withColumn("surrogate_key", expr("uuid()"))
  .option("hoodie.datasource.write.recordkey.field", "surrogate_key")
```

### Q6: 如何调试 Record Key 或 Precombine Field 配置问题？

**A:** 

