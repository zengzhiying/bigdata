# 05 - Snapshot 与 ACID 语义

## 原子提交

一次 Iceberg 写入通常先生成新的数据文件或删除文件，再生成新的 Manifest 和 Metadata JSON，最后通过 Catalog 原子地把表的当前元数据位置更新到新版本。

如果提交失败，未被当前 Snapshot 引用的文件不会成为表的一部分；如果提交成功，新的 Snapshot 就成为后续查询的默认状态。

## 快照隔离

查询在开始规划时选择一个 Snapshot，并在该 Snapshot 上完成扫描。另一个客户端随后提交新 Snapshot，不会改变已经开始的查询所看到的逻辑状态。

这使读操作不需要长时间锁住整张表，同时可以保持一致视图。

## 乐观并发控制

Iceberg 通常采用乐观并发控制：

1. 客户端读取当前表元数据。
2. 客户端基于当前状态生成新文件和新 Snapshot。
3. 提交时确认当前元数据位置没有被其他客户端改变。
4. 如果已经改变，则报告冲突，由客户端重试或放弃。

并发冲突不是数据损坏；它表示客户端需要重新读取最新状态后再决定如何提交。

## Time Travel

只要历史 Snapshot 尚未被过期清理，就可以按 Snapshot ID 或提交时间读取历史数据。Time Travel 适用于：

- 审计某个时间点的数据。
- 对比一次变更前后的结果。
- 恢复误删或误改的数据。
- 为回归测试固定输入版本。

## 快照维护

Snapshot 不应无限保留。生产环境通常根据时间、数量和业务审计要求设置保留策略，并配合：

- 过期旧 Snapshot。
- 清理不再被任何 Snapshot 引用的孤儿文件。
- 监控快照数量和元数据增长速度。

清理操作必须先确认保留窗口和恢复要求，避免过早删除仍需要审计的数据。
