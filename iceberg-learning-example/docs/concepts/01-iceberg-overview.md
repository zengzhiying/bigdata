# 01 - Iceberg 概览

## Iceberg 是什么

Apache Iceberg 是一种面向分析型数据湖的开放表格式。它定义了表的元数据、数据文件组织方式、提交协议和查询语义，使计算引擎可以在对象存储或分布式文件系统上可靠地管理大规模表。

Iceberg 不是计算引擎，也不是对象存储。Spark、Flink、Trino 等引擎负责执行计算，S3、MinIO、HDFS 等系统负责保存文件，Iceberg 负责在两者之间提供表级的事务和元数据语义。

## 它解决了什么问题

传统数据湖通常直接把 Parquet 文件放在目录中，容易遇到以下问题：

- 文件列表和分区目录成为表状态的隐式来源。
- 并发写入时难以保证一致性。
- Schema 变更依赖人工约定，字段重命名可能导致数据错位。
- 更新和删除需要重写大量文件，或者依赖引擎私有实现。
- 查询历史版本、回滚和审计比较困难。
- 不同计算引擎对同一张表的理解不一致。

Iceberg 把表状态显式记录在元数据树中，并使用 Snapshot 表示一次原子提交。查询可以基于某个快照读取，而不必依赖目录扫描来猜测表状态。

## 核心对象

| 对象 | 作用 |
| --- | --- |
| Catalog | 根据名称定位表，并完成表创建、加载和提交。 |
| Namespace | 组织表的逻辑命名空间。 |
| Table | Schema、分区、排序、快照和数据文件的统一逻辑视图。 |
| Data File | 通常是 Parquet、ORC 或 Avro 数据文件。 |
| Delete File | 记录位置删除或等值删除。 |
| Manifest | 记录一组数据文件或删除文件的索引信息。 |
| Snapshot | 表在某次提交后的完整逻辑状态。 |

## 与 Hive 表的区别

Hive 表通常把目录结构和分区目录作为重要的发现机制，而 Iceberg 使用元数据和 Manifest 维护文件集合。Iceberg 的分区转换由表格式管理，查询引擎不需要把分区字段暴露为物理目录字段。

这使得 Iceberg 可以在不重写历史数据的情况下演进分区规范，也可以通过字段 ID 维护 Schema 变更的兼容性。
